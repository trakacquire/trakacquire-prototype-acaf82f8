# TRAKACQUIRE — UI SYSTEM (Proofline)
### Elementos padrão. Nada fora daqui entra em tela sem ADR.
*Subordinado ao DECISIONS.md (D1 · Proofline).*

---

## 1. PRINCÍPIOS (decidem casos não previstos)

1. **Object-first** — integrações, domínios, pessoas e campanhas são objetos com cabeçalho, estado, metadados e ações próprias.
2. **Progressive disclosure** — a complexidade aparece quando necessária; nunca toda de uma vez.
3. **Proof over noise** — mais evidência, menos ornamento. Cor comunica estado, não decora.
4. **Physical confidence** — superfícies, profundidade sutil e materiais tornam o software tangível; zero estética de cassino.
5. **Densidade de operador** — quem usa vive de dado; tela é ferramenta de trabalho, não landing.

---

## 2. TOKENS

### Cor — superfícies e texto
```
--ink:       #0A0A0B   fundo raiz
--iron:      #121214   sidebar, superfície profunda
--graphite:  #1A1A1D   cards, drawers
--zinc:      #28282D   superfície elevada, hover
--line:      #38383D   bordas e separadores
--eggshell:  #F6F1E7   texto primário e CTA primário
--stone:     #A8A6A0   texto secundário
```

### Cor — semântica (uso obrigatório, não estético)
```
--proof-blue: #7C91FF   seleção, identidade, ação contextual, em trânsito
--verified:   #72E6A6   reconciliado, sucesso, FTD confirmado
--warning:    #F1C778   pendente, provisório, divergente, claimed
--critical:   #EF7D8B   falha, bloqueio, órfão, rastro quebrado
```
**Regra:** nenhuma cor semântica pode ser usada por gosto. Verde = reconciliado. Amarelo = pendente/divergente. Vermelho = falha/órfão. Azul = identidade/ação/em trânsito.

### Tipografia
```
--font-sans: Inter            interface, tabelas, texto
--font-display: Inter Display títulos de página
--font-mono: JetBrains Mono   IDs, valores monetários, timestamps, payloads, logs
```
Escala: 11 (label mono) · 12 (secundário) · 13 (corpo tabela) · 14 (corpo desktop) · 16 (corpo mobile) · 18 (título de seção) · 24 (título de página) · 32 (número herói).
**Regras:** nada crítico abaixo de 12px · números **tabulares** em toda tabela financeira · todo ID/valor/timestamp em mono · serifa **somente** em marca e campanha, nunca no produto.

### Espaçamento e forma
```
espaço: 4 · 8 · 12 · 16 · 24 · 32 · 48
raio:   6 (chip) · 8 (input/botão) · 12 (card) · 16 (drawer/modal)
borda:  1px --line
sombra: apenas em overlay (drawer, modal, popover)
```

### Movimento
120–180ms, ease-out. Só em: entrada de drawer/modal, mudança de estado, chegada de item no feed ao vivo. **Respeitar `prefers-reduced-motion`.** Excesso de animação é proibido.

## 3. COMPONENTES OBRIGATÓRIOS

### 3.1 Estruturais
| Componente | Regras |
|---|---|
| **AppShell** | Sidebar (5 grupos) + topbar + conteúdo + slot de drawer. Sidebar recolhível em tablet; some em mobile (barra inferior). |
| **WorkspaceSwitcher** | Busca, lista com plano/estado, "criar workspace". Obrigatório para agência. |
| **CommandBar (⌘K)** | Busca universal por qualquer identificador + ações + copiloto. Presente em toda página. |
| **Breadcrumb** | Sempre objeto atual e pai. |
| **PeriodSelector** | Global, persistente entre módulos, com comparação. |

### 3.2 Dados
| Componente | Regras |
|---|---|
| **MetricCard** | Label mono, valor mono grande, delta com cor semântica, meta opcional, sparkline opcional. **Clique abre Evidence Drawer.** Nunca exibe zero quando a fonte está atrasada — exibe estado de frescor. |
| **DataTable** | Colunas configuráveis, ordenação múltipla, filtros, paginação/virtualização, soma no rodapé, seleção em massa, export controlado, densidade de operador (≥40 linhas visíveis em desktop). |
| **EvidenceDrawer** | Fórmula · fonte da verdade · frescor · provisório/reconciliado · modelo e versão de atribuição · eventos formadores · link para o Ledger. **Todo número abre um.** |
| **Timeline** | Eventos cronológicos com fonte, confiança e correlação. Usada em Player 360, Identity Graph, Tenant 360. |
| **JourneyStrip** | Captured → Linked → Registered → Confirmed → Reconciled, com contagem e % de queda; cor semântica por etapa. |
| **FunnelBars** | Etapa, valor absoluto, %, cor por saúde. |
| **LiveFeed** | Item = horário mono, evento, identidade/origem, valor. Chegada com animação sutil. Marcar sintéticos. |
| **ChartFrame** | Título, controles (tempo real / hora-a-hora / comparar), legenda com destaque de até 2 séries, resto esmaecido. Anotações na timeline. |

### 3.3 Estado e governança
| Componente | Regras |
|---|---|
| **StatusChip** | Vocabulário fechado: `Captured` `Linked` `Confirmed` `Reconciled` `Divergent` `Failed` `Policy blocked` `Orphan` `Synthetic`. Cor semântica. Nunca inventar rótulo novo sem ADR. |
| **IntegrationStateBadge** | `disabled` `sandbox` `pilot` `production` `policy-blocked` + versão do adapter. |
| **FreshnessTag** | "atualizado há X" + fonte. Obrigatório em card/tabela cuja fonte pode atrasar. |
| **ApprovalCard** | Plano imutável (hash), impacto calculado, validade, evidências, quem aprova. Mudou o plano → aprovação invalidada. |
| **ConfirmDialog** | Ação destrutiva/cara: descreve efeito, exige digitar o nome do objeto quando irreversível. |
| **AuditRef** | Referência curta de auditoria exibida após sucesso de escrita. |

### 3.4 Entrada
Button (primary eggshell · secondary outline · ghost · danger) · Input/Select/Combobox · DateRange · Toggle · **SecretField** (mascarado, "revelar" auditado, nunca reexibe após salvar) · CodeBlock copiável · FileDrop · **QueryBuilder** (AND/OR aninhado) · TagInput.

### 3.5 Feedback (os 8 estados como componentes reais)
`LoadingSkeleton` · `EmptyState` (valor + pré-requisito + ação, nunca "sem dados") · `PartialDataBanner` · `PermissionDenied` (diz o papel necessário) · `PolicyBlocked` (diz a política e como resolver) · `IntegrationDegraded` · `ErrorState` (mensagem humana + correlation_id copiável + retry seguro + link para Monitoring) · `SuccessState` (com AuditRef).
**Nenhuma página entra em PR sem os 8 implementados.**

## 4. PADRÕES DE COMPOSIÇÃO

- **Página de lista:** header (título + descrição + ação primária) → filtros/chips → DataTable → paginação. Visões salvas no header.
- **Página de objeto (360):** header (nome, StatusChip, metadados, ações) → abas → conteúdo denso → drawer para detalhe.
- **Wizard de setup:** passos numerados verticais, cada um com teste próprio e estado; documentação contextual na coluna direita; "Go live" só habilita com todos verdes.
- **Canvas (Flow Builder):** nós compactos com métrica dentro do nó; painel de propriedades à direita; barra de versões no topo.
- **Dashboard:** hero de prova → KPIs → journey → feed/radar. Nunca mais de 12 KPIs na primeira dobra.

## 5. RESPONSIVO

| Breakpoint | Comportamento |
|---|---|
| ≥1440 desktop | Sidebar fixa, tabelas densas, drawers laterais |
| 1024–1439 | Sidebar recolhível, colunas prioritárias |
| 768–1023 tablet | Sidebar em overlay, detalhe em drawer |
| <768 mobile | Barra inferior (Command · Connect · Signals · Media · Revenue); tabela vira lista de cards; formulário empilhado; Flow Builder = visualização + intervenção simples; ação crítica com confirmação reforçada |

Nenhuma tela mobile é "desktop comprimido" — a hierarquia é reordenada por prioridade de trabalho.

---

## 6. ACESSIBILIDADE (piso, não extra)

Contraste WCAG AA em conteúdo funcional · foco visível em tudo que é focável · navegação completa por teclado (⌘K, setas em tabela, Esc fecha overlay) · rótulo em todo controle · erro associado ao campo · `prefers-reduced-motion` respeitado · área de toque ≥44px em mobile · nunca comunicar estado só por cor (sempre cor + texto/ícone).

---

## 7. CONVENÇÕES DE CÓDIGO

```
components/
  ui/          primitivos (button, input, table, drawer…)
  data/        MetricCard, DataTable, EvidenceDrawer, Timeline, JourneyStrip…
  state/       Loading, Empty, Error, PermissionDenied, PolicyBlocked…
  layout/      AppShell, Sidebar, Topbar, CommandBar
  domain/      componentes de negócio (LinkCard, PlayerHeader, FlowNode…)
```
Regras: primitivo **nunca** conhece domínio · nada de cor hardcoded (só tokens) · nada de string de status solta (usar o enum do StatusChip) · toda tabela usa `DataTable` (proibido `<table>` avulso) · todo formulário usa os componentes de input padrão.

---

## 8. PROIBIDO

Gradiente decorativo · glassmorphism · sombra colorida · ícone com significado ambíguo · cor semântica fora de significado · animação de entrada em lista longa · toast para erro crítico (usar ErrorState) · modal para conteúdo consultivo (usar drawer) · placeholder como rótulo · "Submit"/"Enviar" genérico (o botão diz o que faz) · página sem estado vazio · número sem evidência.
