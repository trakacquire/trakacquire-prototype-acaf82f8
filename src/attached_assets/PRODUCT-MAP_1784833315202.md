*Subordinado ao DECISIONS.md. Em conflito, DECISIONS prevalece.*

## 0. LEIS DE ARQUITETURA (valem para toda página)

1. **Zero página órfã.** Toda página é alcançável por menu, por link contextual de outra página, ou por resultado de busca. Se não é alcançável, não existe.
2. **Toda página responde a um job.** Se não dá para escrever "o usuário X vem aqui para Y", a página é cortada.
3. **Todo número abre evidência.** Qualquer métrica exibida abre o *Evidence Drawer*: fórmula, fonte, frescor, estado (provisório/reconciliado), eventos formadores.
4. **8 estados obrigatórios por página:** loading · vazio com próximo passo · dado parcial/frescor · sem permissão · bloqueado por política · integração degradada · erro com retry e correlation_id · sucesso com referência de auditoria.
5. **Objeto tem página própria.** Domínio, integração, link, pessoa, campanha, fluxo, tenant: cada um tem cabeçalho, status, metadados, abas e ações.
6. **Ação destrutiva ou cara exige plano + confirmação.** Nunca botão solto.
7. **Três planos isolados:** público · tenant (workspace) · plataforma (super admin). Nunca se misturam na mesma navegação.

## 2. USER FLOWS CRÍTICOS (a espinha da usabilidade)

**F1 · Do zero ao primeiro FTD atribuído (P1)** — o flow que define o produto
`Landing → Signup → Verificação → Wizard de onboarding` →
1. Nomear operação (workspace) e moeda/timezone
2. Conectar **provider de receita (TAP)** → wizard com credenciais → URL de postback copiável → **teste de postback ao vivo** (semáforo verde só com evento real recebido)
3. Adicionar **domínio de tracking** → DNS → verificação automática → SSL
4. Criar **primeiro link** → escolher destino (presell/bot) → link pronto
5. Conectar **bot Telegram** → deep link `?start=` gerado automaticamente
6. Conectar **Meta** (pixel + CAPI) → cobertura de parâmetros exibida
7. **Checklist "Prove seu primeiro FTD"** fixo no Command até o evento acontecer
→ Command mostra `Journey proof` avançando: Captured → Linked → Registered → Confirmed → Reconciled
**Atrito removido:** nenhuma etapa pede sair do produto; cada passo tem doc contextual ao lado, teste próprio e estado "concluído com evidência".

**F2 · Investigar um FTD (P1/P5)**
Command → clique no número de FTDs → lista → clique numa linha → **Player 360** → aba Timeline → clique no evento `first_deposit_confirmed` → **Event Detail** (payload sanitizado, adapter, idempotência) → botão "ver regra de atribuição" → **Attribution Explainer** (qual clique, por quê, janela, confiança).

**F3 · Escalar campanha com segurança (P2)**
Media → tabela com CPFTD real → seleciona campanha → "Simular regra: +20% budget" → **Action Plan** (impacto calculado, amostra mínima, frescor) → Enviar para aprovação → **Approval Center** → aprovar → execução → audit log → resultado no feed.

**F4 · Recuperar base fria (P3)**
Players → query builder ("FTD = não E clique < 7d E origem = Meta") → salvar segmento dinâmico → "Criar broadcast" → composer (mensagem + link rastreado) → **Policy Engine checa consentimento** → agendar → analytics do broadcast até FTD.

**F5 · Atender e converter (P4)**
Inbox → fila → conversa → painel direito mostra origem, campanha, estágio, depósitos, confiança de identidade → responder/macro → marcar evento de conversão → handoff de volta ao fluxo.

**F6 · Fechar o mês (P5/P6)**
Revenue → selecionar período → **Reconciliation** (postback × Reporting API × mídia) → divergências acionáveis → snapshot fechado versionado → exportar/agendar.

**F7 · Onboarding de cliente novo (P9/P10)**
Platform → Tenants → Provisionar → plano e quotas → convite ao owner → acompanhar checklist de ativação do tenant → alerta se travar em algum passo por N dias.

**F8 · Cliente reporta bug (P10)**
Support Console → busca tenant → Tenant 360 → ver health/DLQ/últimos erros → **iniciar impersonação** (motivo obrigatório, tempo limitado, banner visível, tudo auditado) → reproduzir → encerrar sessão → registro no audit.

## 4. PLANO TENANT — app.trakacquire.io

**Estrutura fixa:** sidebar (5 grupos) · topbar (breadcrumb, busca universal ⌘K, seletor de período global, avisos, copiloto, avatar) · área de conteúdo · drawers laterais (evidência, detalhe de objeto).

### GRUPO 1 — OVERVIEW

**1.1 `/command` · Command Dashboard** — *casa do P1*
Conteúdo: cartão **Proof Integrity** (% de FTDs atribuídos + estado da reconciliação) · KPIs financeiros (spend, depósitos, saques, net deposit, payout, lucro, ROI) · KPIs de eficiência (cliques, leads, registros, FTD, CPL, CPReg, CPFTD) · **Journey Proof strip** (Captured → Linked → Registered → Confirmed → Reconciled com % de queda) · **Live Proof Feed** (eventos com impacto real, tempo real) · **Radar** (2-3 anomalias detectadas com o porquê e ação sugerida) · alertas ativos · checklist de ativação (some quando o primeiro FTD reconcilia).
Ações: alterar período · fixar/remover widget · abrir evidência · silenciar alerta com motivo · abrir copiloto.
Entradas: home pós-login. Saídas: qualquer módulo por clique no número.

**1.2 `/analytics` · Analytics (exploração)**
Conteúdo: faixa de métricas principais · **gráfico temporal com granularidade horária** · comparação métrica×métrica (eixo duplo) e período×período (D-1, D-2, 7d, 15d, 30d, custom) · **annotations** na timeline (escalou orçamento, trocou criativo, incidente) · drill-down por dimensão (origem, campanha, conjunto, criativo, geo, device, hora) · **origens** (Meta, TikTok, Instagram, WhatsApp, PDF, orgânico) com ações por origem · **funil de mensagens** (etapas nomeadas até VIP) · dados de atendimento como métrica.
Ações: montar visão · salvar visão · exportar · agendar · adicionar anotação.

**1.3 `/reports` · Relatórios** → `/reports/:id`
Conteúdo: biblioteca (operacional, P&L, coortes, reconciliação, custom) · construtor (métricas × dimensões × filtros) · agendados · snapshots fechados versionados.
Ações: criar · duplicar · agendar (email/Telegram) · exportar CSV/PDF · link expirável · reabrir snapshot (versionado).

### GRUPO 2 — CONNECT

**2.1 `/integrations` · Integration Hub**
Conteúdo: catálogo por categoria (Revenue providers · Acquisition · Messaging · Infra · IA) com card por integração: logo, estado (disabled/sandbox/pilot/production/policy-blocked), versão do adapter, último evento, saúde.
Ações: conectar · abrir objeto · ver documentação · testar conexão.

**2.2 `/integrations/:slug` · Integration 360** (uma página por integração, mesmo template)
Abas: **Visão** (estado, credenciais mascaradas, escopos, versão) · **Setup guiado** (passos numerados com teste em cada um) · **Eventos** (últimos recebidos/enviados) · **Saúde** (latência, erros, rate limit) · **Logs** · **Histórico** (mudanças e quem fez).
Casos: `tap` (postback + Reporting API + reconciliação), `meta` (BM, pixel, CAPI, escopos), `telegram` (bots, webhook, deep links), `whatsapp-cloud` (números, templates, política), `whatsapp-nao-oficial` (instância isolada, termo de risco, saúde do chip), `tiktok`, `kwai`, `sms-voz`, `ia`.

**2.3 `/domains` · Domínios** → **2.4 `/domains/:id` · Domain 360**
Lista: domínio, status (verificado/pendente/inativo), função, região, P95 do redirect, última verificação.
Detalhe: DNS records com estado · SSL e validade · roteamento · **health check com lead sintético** · histórico · pool/rotação (domínio reserva).
Ações: adicionar · verificar agora · definir principal · arquivar.

**2.5 `/tracking` · Links** → **2.6 `/tracking/:id` · Link 360**
Lista: nome, tipo (presell→bot, bot→canal, canal→casa, multi-fonte), domínio, cliques, conversões, CPFTD, estado.
Detalhe: destino e regras (device/geo/hora), split A/B, fallback técnico, QR, parâmetros herdados, histórico versionado, snippet de instalação (SDK).
Ações: criar · duplicar · testar redirect · gerar QR · arquivar.

**2.7 `/tracking/sources` · Fontes & Custos**
Conteúdo: fontes de tráfego com templates de macro por plataforma · ingestão de custo (API ou declarado) · estado do snapshot diário (D+2) · presells/ofertas com health check.

## 7. NAVEGAÇÃO E ATRITO

- **Busca universal (⌘K)** aceita qualquer identificador (email, telefone, click_id, telegram_id, customer_id, event_id) e navega direto ao objeto.
- **Breadcrumb** sempre com o objeto atual e o pai.
- **Drawer em vez de página nova** para detalhe consultivo (evento, evidência); página própria só para objeto que se administra.
- **Período global** persiste entre módulos.
- **Toda tabela**: colunas configuráveis, visão salva, densidade de operador, export controlado.
- **Mobile**: barra inferior por trabalho (Command · Connect · Signals · Media · Revenue); tabelas viram listas; Flow Builder é visualização e intervenção simples; ação crítica exige confirmação reforçada.
